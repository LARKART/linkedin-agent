## Caption

Claude Code just moved from fixed tool to customizable platform.

The new mod layer lets developers write JS/TS functions that intercept tool calls, block or modify them before they execute, and render custom UI panels inside Claude Code itself.

That's a different kind of upgrade than what came before.

Skills extended what Claude Code could know.
Mods extend how Claude Code behaves.

In agent systems generally, the hard part is rarely getting a model to attempt a task. It's controlling what happens around the task — which calls are allowed, what gets logged, what gets stopped before it causes damage, and how a human stays in the loop without slowing everything down.

An interception layer is exactly the kind of thing that problem needs. You're not just prompting the agent anymore. You're defining the boundaries it operates inside.

That's a meaningful shift for anyone building production agent workflows, not just demos.

If you're experimenting with Claude Code already, where would custom interception be most useful in your workflow — approvals, logging, or blocking specific actions outright?

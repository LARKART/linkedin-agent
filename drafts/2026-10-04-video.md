# Draft 2026-10-04 (video)

**Status:** published

**Topic:** Context engineering replaces prompt chat
**Why now:** Builders are actively restructuring Claude setups this week around skill-based loading instead of global context files, driven by real session performance problems with bloated context windows.

## Caption

A one-page SOP outperforms a 40-page manual every time, because nobody reads the manual before doing the task.

That's the same problem showing up in a lot of Claude setups right now.

Many teams built one giant CLAUDE.md file. Every instruction, every edge case, every rule, loaded into context on every single session, regardless of the task in front of the agent.

It felt thorough. In practice, it just made the context window heavier and the agent's attention more diluted.

What builders are shifting toward instead: splitting that knowledge into separate skills that only load when the task actually calls for them. The agent doesn't carry the full manual into every conversation. It pulls the relevant section when the work requires it.

This is just how operations teams already document real workflows. Nobody hands a new hire one document covering every process in the company. They hand them the SOP for the task they're doing today.

Agent context is starting to get treated the same way: not one static file to maintain, but a library of focused instructions the agent reaches for on demand.

The reliability gain isn't from a smarter model. It's from giving the agent less to hold onto at once.

If you're building with Claude or any agent framework right now, worth asking: is your context file documentation, or is it a dumping ground?

## Caption

There's a pattern I keep noticing in how people talk about agent reliability.

Something breaks, and the instinct is to say the agent needs more memory. A bigger context window. A smarter vector store. More history to pull from.

But most of the time, that's not the actual gap.

The agent doesn't need to remember more. It needs better documentation of how the business actually works.

What counts as a qualified lead. Which exceptions matter. When to stop and ask a human instead of guessing. What "done" looks like for a given task.

Memory stores raw history. Documentation encodes judgment.

An agent with perfect recall of every past conversation can still make bad decisions if it was never given clear rules, boundaries, and definitions to reason from.

This is why agent systems that hold up in production usually aren't built around bigger memory. They're built around clear instructions, defined tools, explicit guardrails, and a human checkpoint where judgment calls actually matter.

The orchestration around the model is doing more work than the model itself.

If you're building or evaluating an agent right now, it's worth asking: is this failing because it can't remember enough, or because it was never told clearly enough what "good" looks like?

What's been your experience, memory problem or documentation problem?

## Caption

Two separate companies just announced competing standards for how AI agents talk to each other, in the same week.

Meta, Walmart, and Stripe are backing one open agent protocol. Sierra shipped its own Personal Agent Protocol days later.

Neither is arguing about what agents can do. They're arguing about how agents connect to other systems, tools, and each other.

That's a familiar pattern. Every useful piece of technology goes through this phase. The capability exists before the plumbing gets agreed on.

When I build agent workflows right now, I don't bet the architecture on any single protocol winning. The orchestration layer, the tool calling, the guardrails, the memory and retrieval, all of that gets built so it can sit on top of whatever standard ends up mattering. The business logic shouldn't care which protocol wins.

That's the part worth paying attention to if you're building with agents today. Protocols will keep shifting for a while. The workflow design is what actually holds up.

If you're already running agent workflows, where are you feeling the most friction, the tool connections or the actual decision logic?

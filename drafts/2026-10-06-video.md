**Topic:** OpenAI's Decisions API for agent tool-calling
**Why now:** Public beta launched within the last 3 hours, directly tied to how agents choose actions and tools in production

## Caption

OpenAI just shipped a Decisions API in limited preview.

Not a chatbot. Not a general-purpose assistant. A narrow API that takes text or images and returns one answer from a predefined set of options.

The stated use cases: classification, routing, and choosing an agent's next action.

That last one is worth sitting with.

Most teams building agents today handle "what should the agent do next" with prompt engineering and a pile of if/else logic wrapped around a general model. It works, but it's brittle, hard to test, and hard to explain when something goes wrong.

A dedicated API for bounded decisions is a different approach. Instead of asking a model to reason freely and hoping it picks the right tool, you constrain it to a fixed set of possible answers up front.

That's a meaningful shift in how agent architecture gets talked about. Tool selection and routing stop being a side effect of a big prompt and start being their own building block.

What's not yet clear: pricing, exact request/response format, and how this performs against the general-purpose approach most teams are using today. OpenAI hasn't published that detail, and it's still limited preview, not something you can build on generally yet.

But the direction is the interesting part. If routing and next-action selection become a standard primitive rather than something every team hand-rolls, that changes how agent systems get designed.

What's your agent stack doing today for tool selection: a big prompt, a rules engine, or something in between?

## Caption

There's a pattern showing up across engineering teams right now: AI coding agents are producing a lot more code. The amount of shippable, maintained software isn't growing at the same rate.

That gap is the interesting part.

Swipe through for what's actually happening:

- Your agent shipped 10x more code this month
- Code volume is up. Shippable software isn't
- Agents optimize for output, not outcomes
- Where the gap actually gets created
- Treat the agent like a fast junior engineer
- Engineering discipline becomes the differentiator
- Measure shipped software, not lines generated

An agent will happily generate a working-looking function, a new endpoint, a full feature branch, in minutes. What it won't do on its own is decide whether that code fits the architecture, handles the edge cases, or should exist at all.

That judgment still sits with a human.

The teams getting real value out of these tools aren't the ones generating the most code. They're the ones who kept their review process, their testing discipline, and their architectural standards intact while the agent took over the typing.

More output without more oversight just moves the bottleneck. It doesn't remove it.

If you're building with Claude Code or similar tools, what's the current ratio of agent-written code that actually makes it to production without rework?

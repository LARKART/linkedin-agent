## Caption

There's a pattern in the current discussion around coding agents underperforming their demos.

The common assumption is that the model isn't smart enough yet.

But the more detailed breakdowns point somewhere else entirely: context handling and tool orchestration.

An agent can be excellent at writing code and still fail in production because:

- it loses track of earlier context
- it calls the wrong tool at the wrong step
- it doesn't know when to ask instead of guess
- error handling around it is thin or missing

That's not a model problem. That's an architecture problem.

The same gap shows up outside of coding agents too. A workflow that looks flawless in a demo often breaks the moment real data, edge cases, or multiple steps get involved.

The fix usually isn't a better model. It's better structure around the model: clearer instructions, defined tools, retry logic, and a point where a human checks the output before it goes further.

That's the less exciting part of building with agents. It's also the part that actually determines whether something works on day one hundred, not just day one.

Where have you seen this gap show up, in coding tools or elsewhere?

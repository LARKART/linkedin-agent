**Topic:** Operating systems building containment layers for AI agents
**Why now:** Microsoft shipped Execution Containers 1.0 and Apple is updating macOS to restrict agent disk access within the same 48-hour window, showing both major OS vendors independently reaching the same conclusion about agent risk

## Caption

An AI agent with full filesystem access can read your tax documents, your SSH keys, and your browser history in the same session it uses to rename a folder.

That's the default most agent tools ship with today. Broad permissions, because narrow ones are harder to build and slower to demo.

Platform vendors are starting to push back on that default. The direction is OS-level containment: agents get a defined execution boundary instead of the same access as the logged-in user. Permissions get scoped at the system level instead of trusted to whatever the agent's own code claims it will do.

If that holds, it changes where businesses need to focus.

Right now, most teams handle agent safety themselves. Custom scopes, manual approval steps, someone reviewing what an agent touched after the fact. That works, but it's fragile. It depends on every team building guardrails correctly, every time, for every agent.

OS-level containment moves part of that responsibility down a layer. The operating system decides what's reachable before your workflow logic even runs.

That doesn't remove the need for human-in-the-loop review. It just means the floor is higher. Less depends on someone remembering to scope a permission correctly.

For anyone deploying agents into real business workflows right now, this is worth watching. The permission model you design around today may not be the one you're working with in six months.

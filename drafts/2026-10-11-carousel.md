## Caption

Two separate threads on Hacker News this week dug into the same failure pattern in coding agents working on large, real codebases.

One was a 500-billion-token decompilation experiment. The other was a breakdown of why coding agents feel shallow on hard engineering problems.

Different setups. Same conclusion.

The agents weren't failing because the model was weak. They were failing because the task had no checkpoints.

A giant open-ended prompt like 'refactor this module' gives the agent no way to know if step three was actually correct before it builds step four on top of it. Errors compound quietly until the output looks confident and wrong.

Compare that to a workflow broken into narrow steps: generate a function, run the tests, confirm the output, then move to the next piece. Each step has a validation point before the agent is allowed to continue.

Same model. Same capability. Completely different reliability.

That's the actual lesson from both threads. Coding agents don't need smarter models as much as they need defined checkpoints, feedback loops, and scopes narrow enough that failure shows up immediately instead of three steps later.

Architecture is doing more work than people give it credit for.

Where is your agent currently working without a checkpoint?

## Caption

More pull requests. Same release cadence.

That's the pattern showing up in discussions about AI coding agents right now. Teams generate more code, more commits, more PRs. The number of features that actually ship stays roughly the same.

It's worth sitting with why.

Typing speed was never the constraint in most software teams. Code review, testing, deployment approval, product decisions, and integration work were always the slow parts. An agent that writes functions faster doesn't touch any of that.

This is the same lesson I keep seeing play out in automation work generally. Speeding up one step in a pipeline doesn't speed up the pipeline. If the bottleneck is the handoff between systems, or the approval step, or the review queue, adding velocity upstream just creates a bigger backlog in front of the real constraint.

Before wiring an AI agent into a workflow, it's worth mapping where the process actually slows down. Sometimes it's generation. More often it's the steps around it: review, validation, handoffs between tools and people.

What's the slowest step in your delivery process right now?

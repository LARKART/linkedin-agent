## Caption

Git has no idea what an agent is.

It was built for humans who commit a few times a day, write messages for other humans, and reason about code in files and functions.

Agents don't work that way.

Anthropic published a detailed engineering writeup this week on rebuilding source control around how Claude Code actually reads, writes, and reasons about a codebase. It's getting heavy traction on Hacker News right now, not because it's a product announcement, but because of the problem underneath it.

A few things stood out:

Agents need different commit granularity than humans. A human commits a finished thought. An agent might need to checkpoint every intermediate step so it can backtrack without losing work.

Code isn't the only thing that needs versioning. The context an agent used to make a decision — the files it read, the reasoning it followed — matters just as much as the diff it produced.

This isn't a wrapper on existing dev tools. It's new infrastructure, built specifically for a non-human collaborator.

That's the real signal here. Agent-native infrastructure is becoming its own engineering discipline, not a feature bolted onto tools designed for people.

Most teams adopting Claude Code or similar agents are still running them through tooling built entirely for human workflows — version control, task tracking, documentation — and wondering why things get messy at scale.

The takeaway isn't "switch tools." It's worth auditing where your current stack assumes a human is the one reading, writing, and deciding. Those are the exact points where agents tend to break down.

What's the first piece of your stack you'd rebuild if you assumed an agent, not a person, was using it?

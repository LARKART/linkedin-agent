## Caption

There's a growing conversation about AI coding agents producing huge amounts of code without a matching increase in working, maintained software.

That distinction matters.

Lines of code were never the real output of a software team. Working systems were. Code that handles edge cases. Code someone can still read in six months. Code that fails safely instead of silently.

An agent can generate a working-looking function in seconds. It can also generate ten versions of that function across a codebase, each slightly different, none of them the one someone will remember to update.

Volume isn't the hard part of software. It never was. The hard part is deciding what the system should do, handling the cases nobody mentioned in the spec, and keeping it maintainable once three more features get bolted on.

Agents are very good at the first part now. The second part still needs a person who understands the business logic, not just the prompt.

This is probably why "productivity" is getting harder to measure honestly. More commits isn't the same signal it used to be.

The teams getting real value aren't the ones generating the most code. They're the ones treating agent output as a draft that still needs review, structure, and ownership.

What are you actually measuring when you check if AI is helping your team ship?

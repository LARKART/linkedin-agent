## Caption

There's a headline going around from Anthropic's engineering team about rethinking source control for AI-generated code.

I haven't seen the full writeup, just the framing, so take this as a question rather than a conclusion.

But the premise is worth sitting with.

Git was built around a simple assumption: a human sits down, makes a change, writes a commit message, and does this a handful of times a day.

Agentic coding breaks that assumption. If an agent is generating commits continuously, the bottleneck probably isn't how fast code gets written. It's whether anyone can meaningfully review, track, and roll back that volume of change.

If that's actually what's happening inside teams shipping with Claude Code or similar tools, it raises a real question for anyone building this way right now.

Are we just going to keep bolting agents onto tooling designed for human pacing? Or does reviewing AI-generated code need its own workflow, not just a faster version of code review?

I don't think there's a clean answer yet. But it's the kind of constraint that matters more than model speed.

Curious if anyone here has hit this wall already, where the agent isn't the slow part anymore, the review process is.

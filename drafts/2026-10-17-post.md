## Caption

A Postgres release just got delayed because AI code review found more bugs than the maintainers could triage.

Not because the bugs were unfixable. Because there were too many to evaluate at once.

This is worth sitting with.

For years, the assumption was that better detection equals better software. Find more issues, fix more issues, ship something more solid.

But once a reviewer can flag issues faster than humans can decide which ones matter, detection stops being the constraint.

The new bottleneck is judgment: which bugs are actually worth fixing right now, which are edge cases, which are noise, and who has the context to make that call.

That's not a tooling problem. It's a process problem.

I see the same pattern in businesses adopting AI agents and automation. The hard part was never getting an agent to find anomalies, flag leads, or surface exceptions. It's building the triage layer around it: what gets escalated, what gets auto-handled, what waits for a human.

More AI output without a prioritization system just moves the backlog somewhere else.

What does your team do with the extra signal once the tooling starts outperforming your capacity to act on it?

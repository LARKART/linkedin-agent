## Caption

219 comments on a 125-point HN post. That ratio alone tells you something: this topic is hitting a nerve.

The thread was about developers shipping code their AI agent wrote, code they can't fully explain or debug themselves.

Not a hypothetical. A live anxiety among people writing production code right now.

Here's the shift nobody planned for. The skill used to be writing the code. Now it's reviewing it.

That sounds like a small change. It isn't.

Writing code, you build understanding as you go. Reviewing code someone (or something) else wrote, you have to reconstruct that understanding after the fact, under time pressure, often without wanting to admit you're not sure.

Speed exposed a gap nobody solved first. Agents got fast enough to generate working code before teams figured out how to validate it at the same pace.

That's where blind trust creeps in. Not as a decision. As a shortcut nobody noticed they took.

Fast code and owned code are not the same thing. A team can ship quickly and still have nobody who can answer "why does this work" when something breaks at 2am.

The fix isn't slower AI. It's treating review as part of the workflow, not a step bolted on after.

## Caption

Claude Code has been writing users' email addresses into the User-Agent header of its outbound web requests.

That header gets sent to every site the agent touches during a session. Not stored locally. Sent out, to third parties, as part of normal use.

A developer filed the bug on Anthropic's own GitHub repo. A separate, earlier report found the same email showing up in git commits, overriding a correctly configured user.noreply identity. No setting existed to turn it off. The mechanism is simple: Claude Code reads your account email from a local config file and quietly tells the model "the user's email address is..." at the start of every session.

Anthropic shipped a fix, a built-in privacy mod enabled by default from version 2.1.317. Then another instance of the same behavior got reported in November. Whether that's a recurrence or a new variant isn't confirmed yet.

This is the part worth sitting with if you're giving any agent tool access: the risk usually isn't the model doing something malicious. It's the model including context you never asked it to include, because that context was sitting in a local file it had permission to read.

When I scope what an agent can access, the question isn't just "what can it do." It's "what does it know by default, and does any of that leave the room when it makes a request."

Worth checking what your coding agent has read access to right now, and where that data goes when it talks to the outside world.

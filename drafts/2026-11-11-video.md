## Caption

A codebase can grow fast and still get harder to work in every week.

That's the pattern showing up in developer discussions right now. Teams ship AI-written code quickly, tests pass, features ship. Then six weeks later nobody can explain why a function works, because nobody wrote it line by line.

The code runs. It just isn't understood.

This isn't an argument against using Claude Code or any coding agent. It's an argument for treating the output the way you'd treat a pull request from a new contractor. Read the diff. Ask why a function was structured that way. Reject the parts that solve the problem in a way nobody on the team can maintain.

Speed from an agent only holds up if a human still owns the architecture. Once nobody can draw the system on a whiteboard from memory, every future change gets slower and riskier, not faster.

The fix is boring: mandatory review before merge, same as always. The agent changes how fast code gets written. It doesn't change who has to be able to explain it later.

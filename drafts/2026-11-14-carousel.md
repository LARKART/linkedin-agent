**Why now:** Fresh incident (3 hours old) with real velocity on HN showing people are actively reacting to agent autonomy failures right now.

## Caption

A University of Chicago law professor asked Claude to update page numbers in an old set of lecture notes.

Instead, it deleted his current syllabus and a full folder of 2023 class notes.

William Baude shared the story publicly after recovering the files through Dropbox. The task was small. The permissions were not.

This is getting attention right now because it names the actual gap in how most people use agents.

Most agent setups are built around one question: can it do the task.

Few are built around the second question: what else can it touch while doing it.

A page number fix and a folder deletion live on completely different risk levels. Most tools don't separate them. The agent that can edit a file can usually also delete one, move one, or overwrite one, with the same permission set.

The fix isn't less autonomy. It's a confirmation step sitting between the agent and anything destructive or irreversible. Delete, overwrite, bulk move, send. Actions that can't be undone should not run on the same trust level as actions that can.

If you're already handing agents access to files, inboxes, or records, worth checking: does yours ask before it deletes anything?

What's the one action you'd never let an agent do without a human checking first?

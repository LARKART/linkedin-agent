## Caption

New Harvard research is getting traction on Hacker News this week, and it challenges a simple assumption: that faster code generation means faster shipping.

The finding is that as AI coding agents produce more code, the bottleneck in software teams shifts downstream to code review.

Think about what that means for how teams are structured right now.

Writing code used to be the expensive step. Review was the quick check before merge. If agents can write a feature in minutes, the team's real constraint becomes how fast a human can read, verify, and trust that output.

This is the same pattern I see when I design agent workflows for businesses. The model doing the work is rarely the hard part. The hard part is building the checkpoints around it: what gets reviewed, by whom, under what conditions, and what gets flagged instead of auto-approved.

Skip that design work and faster output just means a faster pile-up at the review stage.

If you're running coding agents on your team, where is the actual bottleneck now? Writing, reviewing, or deciding what even needs a human to look at it?

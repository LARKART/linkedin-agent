## Caption

An AI agent is only as careful as the weakest connector it talks to.

Most businesses think about AI risk at the model level. Is it hallucinating, is it biased, is it saying something wrong. That's the wrong layer to worry about right now.

The real risk is the supply chain around the agent.

MCP made it simple to plug an agent into mail, CRM, drive, issue trackers, anything with an API. Every one of those connections is a small trust decision. You're not just trusting the AI vendor anymore. You're trusting whoever built that connector, however they chose to store credentials, and whatever permissions they asked for.

Independent security research this year has been pointing at the same pattern. Credentials get stored in local config files. Setup instructions often involve pasting in a string that contains the actual keys. Anyone can publish a connector, so the bar for getting into an agent's toolset is low.

The part worth sitting with: a lot of these connectors are opaque. You can see that an agent has access to a mail or CRM connector, but not always what that connector actually does with the data it touches, or who maintains it.

That's the gap. Not the model. The thing standing between the model and your systems.

If you're building or buying agentic workflows, the useful exercise isn't asking what the AI can do. It's asking what every connector in that stack can reach, and whether anyone has actually looked at how it handles credentials.

Treat each connector like a vendor you're onboarding, not a feature you're switching on.

If you're not sure what your agent's connector list actually has access to right now, that's worth checking before adding the next one.

What's the most repetitive part of your workflow right now, and how many tools does it already touch?

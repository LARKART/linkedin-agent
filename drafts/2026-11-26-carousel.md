## Caption

Every agent project I look at has the same folder somewhere. Prompt_v2_final. Tool_configs_copy. A pile of instructions one person wrote for one client, that nobody else can reuse without opening the file and rewriting half of it.

Anthropic just moved Claude Skills onto MCP, in public beta.

That sounds like a protocol update. It is actually a packaging change.

Right now, most teams building with Claude Code treat skills as prompt files sitting inside a project. Useful once, forgotten once the project ships. If another team wants the same capability, they rebuild it from scratch, slightly differently, with its own bugs.

Putting skills on MCP means a skill can be defined once and exposed as something other agents and other projects can call, the same way MCP already lets a model reach a database or an API. Instead of copying a prompt into a new repo, you point a new agent at the skill.

That is the real shift. Not smarter prompts. Shareable ones.

It does not remove the need for oversight. A portable skill still needs someone checking what it is allowed to touch and what happens when it fails. Packaging a capability so it travels well is different from trusting it to run unsupervised.

Teams that start treating skills like components, versioned, documented, reused on purpose, are going to spend a lot less time rebuilding the same logic for every new client or project.
